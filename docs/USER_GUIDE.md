# 使用说明

[中文首页](../README.zh-CN.md) | [English guide](USER_GUIDE.en.md) | [故障排查](SUPPORT.md)

适用于稳定版 v0.3.0，内部 App 版本为 0.3.0，构建编号为 5，运行要求为 macOS 13+ / Apple Silicon。详见[英文发布说明](releases/v0.3.0.md)。

## 1. 首次启动

1. 在 Finder 中打开 `SCMX-build-work.app`。需要 macOS 13 或更新版本及 Apple Silicon Mac。
2. 默认界面为 English，可在左侧底部或工具设置中切换为简体中文，选择会自动保存。外部工具日志和部分旧诊断保留原语言。
3. 看到主窗口后，先按下一节选择工具。

第一次启动时，工程目录、工程、芯片和固件均为“未选择”。工具路径可以自动发现，但不会自动替你选板子或导入旧 App 的使用记录。更新 App 时，你已经保存的配置会保留。

需要清空已保存的工程和芯片选择时，在“工具与固件包”点击“清空工程与芯片选择”。此操作不删除工程文件，并保留工具路径、语言和侧栏顺序。

只查寄存器定义，可直接打开“寄存器助手”选择型号，不需要先安装 CubeMX、创建工程或接上开发板。

直接打开 App 就能使用，不需要 Xcode。只有自己编译这个 App 的源码，才需要 Apple Command Line Tools。

打不开时，先看系统提示，再看[故障排查](SUPPORT.md)。当前包只有 ad-hoc 本地临时签名，没有 Developer ID 签名或 Apple 公证，不要为此全局关闭系统保护。本次发布只提供 Apple Silicon 包，Intel 源码构建尚未验证。[v0.3.0 发布页](https://github.com/aili266/SCMX-build-work/releases/tag/v0.3.0)仅供仓库成员访问，仓库保持私有，没有公开下载。

已有 ELF、HEX 或 BIN 固件？选好烧录工具后，可直接跳到第 5 节，不必导入或编译工程。

## 2. 选择工具

打开“工具与固件包”，点击“自动查找并检查”。只为要做的操作选择工具：

| 要做什么 | 需要选择什么 |
| --- | --- |
| 从工程编译固件 | ARM GCC、CMake、Ninja |
| 生成工程 | CubeMX 和对应的已解压固件包 |
| 用 ST-Link 或 CMSIS-DAP 烧录 | OpenOCD；也可用 CubeProgrammer 配合 ST-Link |
| 用串口或 USB 下载 | CubeProgrammer 的 `STM32_Programmer_CLI` |
| 调试程序 | OpenOCD、ARM GDB |

检查通过后，会显示工具的路径和版本。ARM GCC 的目标应为 `arm-none-eabi`。

找不到工具时，确认选中的是实际运行文件，而不是安装器或整个 `.app`。CubeProgrammer 可以在 Finder 中右键“显示包内容”，再到 `bin` 目录里找。Apple Silicon 选 macOS Arm 安装包。

工具需要自行安装，App 不附带这些软件。编译 STM32 使用 ARM GCC、CMake、Ninja，不使用 Xcode。Homebrew 若要求 Command Line Tools，那是安装软件包的需要，不是运行 App 的需要。

只烧录已有固件，不需要 CubeMX 或固件包。其他工具缺失的提示，不一定影响这次烧录。

## 3. 导入或新建工程

1. 选择“总目录”。例如新建 `stm32_project` 文件夹；不要选单个工程的文件夹。
2. 选择芯片系列，再导入工程。导入会复制文件，原工程保留。
3. 要新建工程，点“新建工程…”，填名称、选芯片，再点“创建并生成”。之后可用“打开 CubeMX”配置引脚、时钟和外设，保存后回到 App 重新生成。

**成功时：**能在工程列表中选中工程，并看到它的路径。

**没有找到工程时：**先检查总目录和导入目录，确认 `.ioc` 文件在哪里。

烧录页只有一个“芯片系列”选项，直接选 STM32F1、STM32G4 等，再选具体型号。软件会自动处理 Fseries、Gseries 目录分类，也可以从工程 `.ioc` 中识别芯片。型号列表合并了内置设备包映射和本机 CubeMX 数据；新建工程仍需在 CubeMX 安装对应型号和固件包。列表里的型号不代表都已实测。

## 4. 生成并编译

1. 选中工程，点击“生成工程”。
2. 生成完成后，在“工程与编译”或烧录页操作行点击“编译工程”。两处使用同一个构建流程。
3. 编译成功后，App 会选用识别到的输出作为固件；无法确定输出时，会提示选择正确的 ELF、HEX 或 BIN。

带锤子图标的“编译工程”需要先选中工程。正在执行其他操作或调试连接未断开时，按钮也不可用。编译不会自动烧录，烧录前仍需核对固件。

编译通过后，会列出生成的固件文件。

编译失败时，先看日志里最早出现的错误。找不到工具就回第 2 节；找不到源文件就检查工程路径。换工程或工具链后仍出现旧缓存错误，可以重置构建缓存，旧输出会移走保留。

“整理工程目录”用于整理 CubeMX 的 `Projects` 层级。先备份工程。只有 `.ioc`、还未生成构建文件时，此操作会拒绝执行，并提示先点“生成工程”；它不代替生成工程。

多核、TrustZone 和 MP/Linux 工程需要单独配置，不能直接套用普通单核工程流程。

用 VS Code 时，打开实际工程根目录。成功配置 CMake 后才有编译数据库；补全需要 C/C++ 扩展，编辑器内调试需要 Cortex-Debug。

## 5. 烧录固件

要在烧录页重新编译，先选中工程，再点操作行中的“编译工程”。编译后核对选中的输出，再进行“烧录并校验”。窗口较窄时，操作按钮分为两行显示。

### 常用方式：ST-Link / CMSIS-DAP

1. 打开“烧录工作台”，选芯片型号。
2. 后端选 OpenOCD，选探针和对应芯片的目标 `.cfg`。速度可先用 1000 kHz。
3. 接好开发板电源、共地、SWDIO 和 SWCLK，点击“连接检测”。
4. 检测成功后，选择固件。BIN 还要填正确的写入地址。
5. 点放大镜预览命令，再点“烧录并校验”。核对芯片、文件和地址后确认。

**成功时：**连接检测能读到芯片内核和 Flash 信息；烧录结束后能看到校验结果。不要只凭“进度走完”判断成功。

**连接失败时：**先关掉占用探针的 IDE 或调试器，再查接线、供电和目标配置，必要时降速。不要反复擦除来尝试修复连接。

多个探针要填序列号。“复位下连接”还需要 NRST 接线，且探针和目标配置支持。

### 用 CubeProgrammer 烧录

- **ST-Link：**后端选 CubeProgrammer，连接方式选 SWD。点“列出设备”，填写需要的序列号，再选固件烧录。此处不支持 CMSIS-DAP。
- **串口：**连接方式选 UART，选真实的 `/dev/cu.*` 端口和波特率。先断开占用该端口的串口终端。下载成功后，恢复开发板正常启动方式并复位。
- **USB：**连接方式选 USB DFU。让芯片进入系统下载模式，接芯片的 USB 数据口，再点“列出设备”，填 USB1/USB2 或序列号。

**失败时：**先看所选接口、端口和启动方式，再看工具返回的错误。CubeProgrammer 实际 CLI 行为及 UART、DFU 开发板流程仍待实测，命令检查通过不代表实物已验证。

串口下载只能用芯片手册规定的下载引脚。用 3.3 V TTL，TX/RX 交叉并共地，不能直接接 RS-232 电平。下载使用偶校验，由 CubeProgrammer 设置。USB DFU 也不是所有芯片都支持；ST-Link 的 USB 口不是芯片的 DFU 口。

### 校验、擦除和复位

- “仅校验”不写入或擦除，但 OpenOCD 会复位、暂停目标，成功后再运行。
- OpenOCD 擦除只处理 **Bank 0**，完成后保持暂停。
- CubeProgrammer 擦除执行 **`-e all`（全部擦除）**。确认范围后再点确认。
- 读取、校验或烧录出错后，芯片可能仍暂停。重新连接，确认运行状态。

## 6. 读取备份和选项字节

1. 在烧录页填起始地址和字节数。例如 `0x08000000`、`65536` 表示读 64 KiB。
2. 点“读取备份…”，选一个不存在的新文件名。
3. 成功时，生成的 BIN 文件长度会经过检查。

**失败时：**先核对芯片地址范围和长度，再看是否已有同名文件。单次最多 16 MiB；软件能检查数字和地址溢出，不能确认输入范围都是有效 Flash。

OpenOCD 读取会复位并暂停目标，成功后运行，不能用于不中断的实时抓取。读取失败后确认芯片是否仍暂停。本轮尚未实测开发板读取。

“读取选项字节”只在 CubeProgrammer / SWD 下可用，只显示结果。不提供读保护修改、解除保护、OTP 写入等不可逆操作。

## 7. 使用串口终端

1. 在烧录页下方选串口和波特率，点“连接”。设备也要使用 8N1。
2. 发文字时选文本模式，按需要勾选 CRLF 换行；发字节时选 HEX，例如 `01 A0 FF`。
3. 点发送或按 Enter。成功时看到收发计数变化；是否有回复取决于设备程序。

**没数据时：**先查端口、波特率和接线，再确认端口没有被其他程序占用。设备拔掉后需要重新连接。

Mac 的端口通常叫 `/dev/cu.usb…`，不是 COM3。软件每 3 秒刷新列表，不会逐个打开端口寻找开发板，只有你点连接或下载时才使用选中的端口。

波特率可选 9600、19200、38400、57600、115200、230400。文本按 UTF-8 发送；HEX 必须是完整字节。每次最多发送 4096 字节，部分发送会报告实际数量。

接收区只留最近 64 KiB，保存导出的是这部分原始字节，不是全部历史数据。收发计数从上次清空起累计，可能大于当前保留的数据量。

## 8. 调试程序

1. 打开调试页，选本次编译的 ELF 和匹配芯片的 OpenOCD 目标配置。
2. 连接后点暂停。成功时能看到调用栈，并可查看变量或内存。
3. 按需继续、单步、进入函数、复位暂停，或运行到 `main`。断点可填函数名或 `文件:行号`。
4. 切换调用栈中的帧，可看该帧的参数和局部变量；监视区可填数组或结构体成员表达式。

**连不上时：**先查 OpenOCD 和 ARM GDB 路径，再关闭占用探针或本机 `3333` 端口的程序。烧录页选 CubeProgrammer，也不改变调试所需工具。

**变量看不到时：**先确认是带调试信息的 Debug 构建，优化建议用 `-O0` 或 `-Og`。优化掉、超出作用域或没有符号的变量可能不可见。“全部栈变量”不等于能把任意内存还原成变量名。

调试连接未断开时，App 会阻止普通后台操作。操作前先断开调试。本轮未实测在线调试。

## 9. 读取寄存器

1. 打开“寄存器助手”，选择芯片系列和型号，内置定义会随型号切换。
2. 按外设类型和实例筛选，例如 GPIO → GPIOA、I2C → I2C1，也可搜索寄存器名称或地址。多核型号有多份定义时，另选内核。
3. 要读实际值，先到调试页连接并暂停匹配的芯片，再返回点寄存器右侧的读取按钮。只写寄存器不开放读取。

**读不到时：**先查芯片型号、地址和外设时钟，再对照该型号参考手册。

定义来自厂商 SVD 和官方设备包的型号映射，离线可用。没有匹配定义的型号会明确提示，不会套用 F1 或 G4 地址。多个型号可能共用一份厂商定义，可选外设和封装引脚请以芯片手册为准。寄存器说明保留厂商原文。

界面不提供写入，但读取仍可能清除标志或改变外设状态。厂商标记了读取副作用的寄存器，会在读取前要求确认。一个型号有多份内核或安全域定义时，目前只开放离线查看；调试目标的对应切换尚未接入，因此不开放实时寄存器读取。

## 10. 整理代码文件

v0.3.0 继续隐藏这个实验功能，侧栏排序中也不会显示。源码和回归测试仍在仓库里，操作预览、撤销和复杂工程适配仍需完善。

“工程与编译”中的导入工程、CMake 配置、编译和“整理工程目录”不受影响。这次更新不会删除用户文件，也不会移除之前生成的 CMake 片段。

## 11. 配置、日志和求助

- **复用连接：**导出连接配置，到另一台 Mac 导入。还需重新选工具、端口和设备；导出文件不含这些路径和设备序列号。
- **调整侧栏：**使用左下角的排序入口。
- **操作失败：**先看错误提示，再查看或保存运行日志。若日志区空白，不代表操作成功。
- **提交问题：**记录操作步骤、芯片和板卡型号、工具版本、macOS 版本。日志先去掉用户名路径、设备序列号和令牌；不要上传无权分享的代码或固件。

设置与旧 App 隔离，保存在 `~/Library/Application Support/SCMXBuildWork/settings.json`。

日志只保留最近约 15 万至 18 万个 UTF-16 单元，保存导出的也是这部分内容，不是全部历史。重要错误请及时保存。

v0.3.0/build 5 的本地测试已通过，包括工程 137 项、隔离用户目录启动 29 项，以及中英文各 426 条文字资源的键名检查。设置、进程、日志、寄存器样例及数据检查和原 `--self-test` 也已通过。窄窗口截图和实际 ARM 固件工程编译仍在进行，尚无稳定版 CI 或实物验证结果。各项数量和待验证内容见[本地验证结果](VALIDATION.md)。

稳定版仍仅面向私有仓库成员。先用工程副本试用；更多问题见[故障排查](SUPPORT.md)。
