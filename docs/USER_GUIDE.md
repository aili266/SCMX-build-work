# 各模块使用说明

## 1. 首次配置

打开“工具与固件包”，点击“自动查找并检查”。选择 CubeMX、CMake、Ninja、ARM GCC、ARM GDB、OpenOCD 的实际可执行文件。ARM GCC 必须返回目标 `arm-none-eabi`。

使用 UART / USB DFU 时，在“CubeProg CLI”选择 `STM32_Programmer_CLI`，不要选择安装器或整个 `.app`。如果自动发现失败，使用 Finder 的“显示包内容”定位其 `bin` 目录。Apple Silicon 使用官方 macOS Arm 安装包。

烧录已有固件不要求安装 CubeMX 或 HAL 固件包；生成工程则需要匹配的 CubeMX 与已解压固件包。工具检查会同时报告构建工具，缺少它们不意味着已有固件无法下载。

## 2. 烧录工作台

选择具体芯片、后端和连接方式。芯片型号可以从当前工程 `.ioc` 识别；数据库来自本机 CubeMX，不代表所有列出的芯片都实测支持。

### OpenOCD / SWD

1. 连接 ST-Link 或 CMSIS-DAP 与目标板，确认供电、共地、SWDIO 和 SWCLK。
2. 选择探针、目标 `.cfg` 和 SWD 速度。初次可用 1000 kHz；不稳定时降速。
3. 多个探针时填写序列号；“复位下连接”需要接通 NRST，且探针/目标配置须支持。
4. 点击“连接检测”，查看日志中的内核与 Flash Bank 信息。
5. 选择 ELF、HEX 或 BIN；BIN 额外填写正确的目标地址。
6. 使用放大镜按钮预览命令，再点击“烧录并校验”确认执行。

“仅校验”不会发出写入或擦除命令，但 OpenOCD 流程会复位并暂停目标用于读取，结束后运行。擦除按钮只擦除 Bank 0 并保持暂停，多 Bank 芯片的其他 Bank 不在此操作范围。

### CubeProgrammer / SWD

选择 CubeProgrammer 后端与 SWD。当前界面仅集成 ST-Link；CMSIS-DAP 使用 OpenOCD。点击“列出设备”查看序列号，按需要填写。下载时先写入，再校验，最后复位。CubeProgrammer 的擦除按钮执行 `-e all`，范围与 OpenOCD Bank 0 擦除不同，确认框会说明。

### CubeProgrammer / UART

选择真实 `/dev/cu.*` 串口、波特率和固件。按照具体芯片的 AN2606/数据手册选择 ROM Bootloader 支持的 USART 引脚和启动方式，不能把任意 UART 当成下载口。3.3 V TTL 串口 TX/RX 交叉，共地；不要使用 RS-232 电平直接连接 MCU。

终端和下载不能占用同一个串口，下载前先断开终端。下载连接使用偶校验，由 CubeProgrammer 配置。完成后按板卡方式恢复正常启动并复位。

### CubeProgrammer / USB DFU

确认芯片支持 ROM USB DFU，并按其手册进入系统 Bootloader。连接芯片的 USB 数据口，点击“列出设备”，输入对应 USB1/USB2 或序列号。不是所有 STM32 都支持此方式，接入 ST-Link 的 USB 口也不等于接入芯片 DFU。

UART / DFU 当前只做协议与命令集成，尚未完成本版本真实设备回归。遇到不支持的校验或读取操作，以后端返回的明确错误为准。

## 3. Flash 备份与选项字节

填写十六进制起始地址和十进制字节数，选择“读取备份…”。示例：起址 `0x08000000`，长度 `65536`，表示读取 64 KiB。

请按芯片实际 Flash 映射填写；软件只验证数字与地址溢出，无法单凭输入判断这段地址是否全部有效。单次上限 16 MiB。读取成功后还会核对文件长度，避免把半份文件保存为完整备份。目标文件已存在时拒绝覆盖，选择新文件名。OpenOCD 读取会复位暂停并在成功后运行目标，不能用于不中断的实时抓取。

“读取选项字节”仅在 CubeProgrammer / SWD 可用，使用显示命令。未提供 RDP 修改、读保护解除、OTP 烧写和不可逆安全配置入口。

## 4. 串口终端

在烧录页下方选择串口和波特率，点击“连接”。终端使用 8N1；波特率为 9600、19200、38400、57600、115200 或 230400。

文本模式发送 UTF-8，可选择添加 CRLF。HEX 模式填写完整字节，例如 `01 A0 FF`，空格可省略，不能填写单个半字节。发送按钮或 Enter 发出数据。

接收区保留最近 64 KiB，RX/TX 计数为自上次清空以来的总量。保存按钮导出当前保留的原始接收字节；它不是无限时长录制器。设备移除时断开并显示原因。单次发送最大 4096 字节；部分发送会报实际发送量，不会假报全部成功。

## 5. 调试

调试依赖 OpenOCD 和 ARM GDB，与烧录页选择的 CubeProgrammer 后端独立。选择包含符号的 ELF，匹配当前工程的 OpenOCD target。推荐 Debug、`-O0` 或 `-Og` 以及调试符号。

连接后可以暂停、继续、复位暂停、运行到 main、单步或进入函数；以函数名或 `文件:行号` 添加断点。暂停后查看调用栈，切换栈帧，读取该帧参数和局部变量。监视表达式可添加数组、结构体成员等有效 GDB 表达式。

“全部栈变量”是当前调用栈中带调试信息的变量；全局变量扫描依赖 ELF 符号，不能把 RAM 中任意字节全部自动还原为变量名。优化掉的值、未进入作用域的变量和缺少调试信息的库可能不可见。

同一探针不要被其他 IDE、CubeProgrammer 或另一个调试会话占用。应用内调试会话未断开时，普通后台操作会被拦截。当前 GDB 服务固定本地 3333 端口，端口占用会报错。

## 6. 寄存器助手

先在调试页连接目标并暂停，再选择寄存器助手。按 GPIO、USART、I2C 等外设及其实例筛选，或搜索寄存器名称，然后读取。

内置表主要覆盖 F1/G4 的常用寄存器，不是所有 STM32 型号的完整 SVD 数据库。地址、访问属性和位意义最终以具体型号参考手册为准；某些状态寄存器读取会清标志，外设时钟未开启或不可访问时会失败。界面不提供寄存器写入。

## 7. 工程与编译

总目录选放置系列文件夹的上级，例如 `stm32_project`；不要将单个工程文件夹误填为总目录。选择系列后导入现有工程，导入使用复制，源工程保留。

新建工程后在 CubeMX 中配置引脚、时钟、外设与固件包并保存。点击“生成工程”，再“编译工程”；应用按需要运行 CMake 配置，输出 ELF/BIN/HEX。多输出时明确选择，不默认随意烧录某一个目标。

“整理工程目录”处理 CubeMX 的 Projects 层级，并为缺少 CMake 的 `.ioc` 工程在临时副本生成缺失构建文件。默认保留已有源码，生成或移动前备份。多核、TrustZone、MP/Linux 工程需要专用配置，不能按单核 Cortex-M 通用工程处理。

使用 VS Code 时打开实际工程根目录。应用生成编译数据库引用、自动配置/构建任务和 Cortex-Debug 配置；代码补全还需要安装对应 VS Code C/C++ 扩展。编译数据库来自成功的 CMake 配置。

## 8. 代码整理

将用户文件命名为 `bsp_led.c`、`bsp_led.h`、`app_control.c` 等，放在 Core/Src 与 Core/Inc。选择“代码整理”后执行，目标示例：

```text
Core/Src/bsp_c/bsp_led.c
Core/Inc/bsp_h/bsp_led.h
Core/Src/app_c/app_control.c
Core/Inc/app_h/app_control.h
```

支持 bsp、app、driver、drv、middleware、service。不存在的目录自动创建；目标已有同名文件则中止，避免猜测覆盖。要求先有根目录 CMakeLists.txt。

预览版会更新已存在的标准 `Core/Src/...` / `Core/Inc/...` 引用，并写入 `cmake/stm32studio-user-files.cmake`，加入用户源文件及头文件搜索目录。重复执行会重新同步已有分类目录。复杂自定义 CMake 表达式和手写相对路径仍需检查生成后的差异，操作前备份位于 `.stm32studio/backups/`。

## 9. 工具、配置与日志

连接配置导出用于复用后端、接口、芯片、速度、模式和 BIN 地址，不携带工具路径、工程路径、固件路径、串口路径和设备序列号。新机器仍需安装工具、选择端口并确认目标。

工具与固件包页面保存实际可执行文件路径。侧栏左下角可调整模块顺序。运行日志显示具体命令、输出和错误，可保存文本文件；反馈或公开日志前检查本机路径、串口标识和序列号。

## 10. 发布前试用

此预览版设置与旧 App 隔离。先用复制的工程测试，再检查真实开发板。不要将未实测的芯片写成“支持全部系列”。审阅通过前不上传个人工程、固件、安装包、设置文件和第三方固件包。
