# SCMX-build work v0.3.0

Stable release for repository collaborators, for macOS 13 or later on Apple Silicon (arm64). The repository remains private. The earlier [v0.3.0-beta.1 release](https://github.com/aili266/SCMX-build-work/releases/tag/v0.3.0-beta.1) remains available.

## Download and open

1. Download the macOS arm64 ZIP and `SHA256SUMS.txt` attached to this release. Check the archive against the checksum file from the same release, then extract it.
2. Open `SCMX-build-work.app` in Finder. Xcode, Apple Command Line Tools, and a Swift compiler are not required to run the packaged app.
3. Select English or Simplified Chinese at the bottom of the sidebar. Select the external tools needed for your workflow under Tools & Firmware Packs.

The internal app version is 0.3.0, build 5. The app is ad-hoc signed, not Developer ID signed or Apple notarized. Do not disable macOS security globally to open it. No Intel binary is provided; Intel source builds remain unverified.

## Changes since the beta

- Build Project is now in the Flashing page action row, with a hammer icon. It shares the existing build workflow with Projects & Build.
- The button requires a selected project and is disabled while another operation is running or a debug session is active. After a successful build, the app selects the identified output as firmware or prompts you to choose when the output is ambiguous. Building does not flash the device.
- The Flashing actions wrap into two rows in narrower windows. The main window title no longer includes Preview.

The experimental Code Organization module remains hidden from both the sidebar and reorder dialog. Its source and regression tests are retained. Project import, CubeMX generation, CMake builds, and project-directory normalization remain available.

A fresh installation leaves the workspace, project, MCU, and firmware unselected. Updates preserve this app's saved settings. Clear Workspace and Device Selection does not delete project files and keeps tool paths, language, and sidebar order.

## Validation and limits

Local build 5 checks passed for settings, isolated-home startup, programming commands, process handling, logs, localization, register fixtures, all 215 bundled register profiles, and the original environment-dependent self-test. Narrow-window UI snapshots and an actual ARM fixture build are still in progress; no v0.3.0 CI result is recorded. See the [validation record](https://github.com/aili266/SCMX-build-work/blob/v0.3.0/docs/VALIDATION.md) for counts and remaining checks. Command tests and temporary-project regressions do not establish physical-device compatibility.

- Physical-board programming, erase, Flash backup, option-byte reads, and live GDB debugging remain unvalidated. CubeProgrammer's real CLI responses still require testing.
- The bundled register library contains 3,822 model/base-name entries across 30 families and 215 profiles. This is definition coverage, not a tested-board list. Unknown models do not use another family's addresses.
- Multicore or multi-security-domain profiles support offline browsing only. Register reads can affect hardware flags.
- OpenOCD erase affects Bank 0 only; CubeProgrammer erase uses `-e all`. Check the displayed scope before confirming.
- External Flash loaders, batch programming, security provisioning, SWO/RTT, and J-Link-specific controls are not included. UART and USB DFU depend on the exact chip's bootloader support.

External tools and ST firmware packages are not bundled.
