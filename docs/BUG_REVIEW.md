# 原有代码检查与修复记录

本次检查覆盖工程整理、构建缓存、固件读取、进程启动/超时和新增下载流程，并阅读了 GDB 会话代码。以下是代码中能确认的具体问题；不宣称已穷尽所有缺陷。

## 已修复

| 问题 | 原因与影响 | 修复方式 |
| --- | --- | --- |
| 固定构建目录切换 Debug / Release 后仍沿用旧构建模式 | 工具链签名仅包含工具路径，不包含构建模式和工程路径 | 在签名中加入工程与配置；配置改变时重新运行 CMake |
| 用户 C/H 文件整理后可能编译失败 | 只移动文件，原有 CMake 路径失效，新头文件目录未加入 | 更新标准路径引用，生成独立用户 CMake 片段并包含；重跑同步且不重复插入 |
| 整理遇到同名冲突会形成部分移动状态 | 原流程边移动边跳过冲突 | 移动前检查全部目标，同名时整体中止；保留备份 |
| 根目录已有 cmake/ 时会遗漏嵌套工具链 | Projects/CMakeLists.txt 被移出，但配套目录被静默跳过 | 迁移前预检 cmake、预设、启动和链接文件；冲突时不修改任何位置，新增 5 类场景回归 |
| CubeMX 重生成后可能丢失用户整理片段引用 | 生成器重写顶层 CMakeLists.txt | 已整理工程在生成完成后重新同步用户片段 |
| 空文件可以通过固件摘要检查 | 只读取属性，没有限制普通非空文件 | 拒绝空文件与非普通文件 |
| 超时只显示普通进程退出错误 | 超时触发终止，但未保留超时原因 | 记录超时状态并返回明确超时错误 |
| 点击停止与启动新进程之间存在竞态 | 启动前检查和实际启动之间没有共同锁保护 | 在进程登记与启动阶段统一检查停止状态 |
| 未安装 CubeMX 时无法选择用于烧录的 MCU | 空型号库会清空手动型号，并只显示空 Picker | 保留手动型号，空数据库时显示系列和型号输入框 |
| 反复报错后界面可能卡顿，日志显示存在空白风险 | 输出逐块排进主线程，大文本反复布局；原白屏现场未能复现 | 合并输出、限制等待显示的内容，改用原生文本控件；重复失败和绘制检查通过 |
| 进程输出缓存没有上限，分块中文可能乱码 | 全量 Data 不断增长，每块独立转成 UTF-8 | 返回内容保留最后 4 MiB，跨块保留未完成的字符 |
| 超时或停止后仍可能等不到输出结束 | 仅终止直接进程，子进程可能仍占用输出 | 为启动的命令建立独立进程组，超时和取消覆盖读取过程，限时终止并回收 |
| 换工具链后旧编译参数仍被复用 | 重新传工具链路径不会清除 CMake 已初始化的参数 | 校验构建目录归属后，只清除 CMakeCache.txt 和 CMakeFiles，再配置 |
| 整理后中间件引用失效 | 原先只修正 Core 和 Drivers | 统一修正生成的工程根路径，验证 FreeRTOS、USB、FATFS 等路径 |
| 只有 .ioc 时误报整理成功 | 生成的必需源码留在临时目录，随后被删除 | 明确提示先使用“生成工程”，整理操作不再自动补写源码 |

## 新增功能检查

测试覆盖：CubeProgrammer SWD/UART/DFU 命令参数、序列号与连接模式、HEX 文本转换、配置迁移、备份地址溢出与不覆盖、烧录确认后固件变化，以及 OpenOCD 连接参数。仅校验路径明确不发出写入或擦除参数。

串口收发使用系统虚拟终端进行实际测试，验证二进制接收和 HEX 发送，不只比较字符串。代码整理使用临时的 C 工程验证归档、已有源文件引用更新、重复执行以及真实 CMake 编译运行。

## 仍需确认的边界

- 新增 CubeProgrammer 命令尚未在本机实际 CLI 和开发板上逐项验证；未安装时给出路径提示。
- 未运行本轮真实烧录、擦除或选项字节操作；没有改变用户开发板。
- 复杂用户 CMake 表达式、自定义子目标、非标准路径不保证自动重写；需要检查差异和备份。
- OpenOCD / CubeProgrammer 超时或错误后，目标可能保持暂停；需重新连接确认运行状态。
- 进程停止覆盖本工具启动的进程组；外部程序若主动脱离该组，不保证一并清理。不会扫描或终止无关进程。
- GDB 调试使用固定 localhost:3333 端口，其他调试器占用时需要先关闭；本次没有更改完整 MI 解析机制。
- 旧的 VS Code 任务通过缓存是否存在决定配置；在编辑器外移动工程或改工具链后，需重置缓存或重新配置。App 自身新增的签名检查不替代 CMake Tools 扩展全部行为。
- 读写保护、外部 Flash、双 Bank、TrustZone、多核和 MP/Linux 流程未完成认证。

这份记录用于审核和跟踪残余风险，具体测试运行结果见仓库测试入口与后续 CI。
